# TAINA — мини-CRM + Sales Engine V1

Единая система вокруг одной Google Таблицы "TAINA — Воронка":

1. **workflow-1** — заявка с сайта (Netlify) → строка в таблице → уведомление в Telegram.
2. **workflow-2** — раз в день напоминание о заявках без ответа.
3. **workflow-3** — поиск потенциальных клиентов на Google Maps (Outscraper),
   оценка через GigaChat, карточка лида в Telegram с кнопками.
4. **workflow-4** — обработка нажатия "Одобрить"/"Отклонить": меняет статус в
   таблице. Сообщение компании система **никогда не отправляет сама** — вы
   решаете и пишете вручную.

Никакой лишней инфраструктуры: только n8n (у вас уже развёрнут на Amvera) +
Google Таблица через один скрипт + Telegram + GigaChat-credential (уже
настроен у вас в n8n под именем "GigaChat").

## Про репозиторий и форму сайта

В репозитории `clawdbot1` нет сайта TAINA Studio и HTML-формы заявки — этот
репозиторий с сайтом не связан. Поля формы (name/email/phone/company/message)

поля к простому виду" в workflow-1 правильно их прочитала (см. раздел "б"
ниже, шаг про эту ноду).

## Что проверено по документации, а что нет (честно)

Из этой рабочей среды был заблокирован прямой доступ к docs.netlify.com,
docs.n8n.io, developers.google.com и docs.gigachat.ai — сработал только
веб-поиск (по кэшу, не прямой заход на страницы). Поэтому:

**Подтверждено через официальные страницы (по результатам поиска, ссылающимся
на них):**
- n8n Webhook, Telegram (Send Message, Callback operations, Telegram Trigger
  на callback_query), Schedule Trigger, Loop Over Items (Split in Batches,
  выходы "loop"/"done") — поведение и основные параметры.
- Google Apps Script: `doGet(e)`/`doPost(e)`, `e.postData.contents`,
  `ContentService` для JSON — стандартные механизмы Web App.
- Outscraper Google Maps API: работает по параметру `query` (ниша + город),
  поддерживает синхронный и асинхронный режим, отдаёт поля вроде `name`,
  `site`, `category`, `phone`, `full_address`.
- GigaChat: OpenAI-совместимый формат `chat/completions` (`messages` с
  `role`/`content`), базовый адрес `https://gigachat.devices.sberbank.ru/api/v1`.

**НЕ удалось подтвердить вживую (используйте с проверкой перед боевым
запуском):**
- Точный URL и названия параметров Outscraper API (`/maps/search-v3`,
  `query`, `limit`, `async`) — в workflow-3 есть заметка-предупреждение прямо
  на холсте n8n. **Перед первым реальным запуском сверьте с примером кода в
  вашем личном кабинете Outscraper (там показывают actual curl-пример для
  вашего аккаунта).**
- Точную структуру ответа Outscraper (список компаний может лежать в
  `data[0]` или прямо в `data` — код в workflow-3 проверяет оба варианта
  защитно).
- Порядок выходов "loop"/"done" у ноды Loop Over Items — n8n подписывает их
  прямо на холсте, я оставил заметку рядом с нодой в workflow-3, проверьте
  подписи после импорта.
- Точную структуру JSON, которую Netlify присылает в исходящий webhook —
  нода "Привести поля к простому виду" в workflow-1 проверяет оба
  распространённых варианта (поля прямо в теле или вложены в `data`).

## а) Google Таблица + Apps Script

1. Создайте Google Таблицу с названием **"TAINA — Воронка"**.
2. В первую строку первого листа впишите заголовки колонок **ровно в таком
   написании** (порядок не важен, скрипт ищет по названию):

   ```
   ID | Дата добавления | Компания | Сайт | Отрасль | Источник | Контакт (ЛПР) |
   Канал связи | Score (0-100) | Возможная проблема (гипотеза) | Что предложить |
   Статус | Дата первого контакта | Дата последнего контакта | Следующее действие |
   Дата следующего действия | Ответ клиента | Продукт | Сумма (₽) | Комментарий
   ```

3. Расширения → Apps Script → сотрите содержимое `Code.gs` по умолчанию →
   вставьте код из [`apps-script/Code.gs`](./apps-script/Code.gs).
4. Задайте токен: шестерёнка "Настройки проекта" → "Свойства скрипта" →
   добавить свойство `WEBHOOK_TOKEN`, значение — длинная случайная строка
   (например, UUID с https://www.uuidgenerator.net). Запишите его — он
   понадобится в n8n. **Нигде, кроме n8n, его больше не вставляйте.**
5. Кнопка "Развернуть" → "Новое развёртывание" → тип "Веб-приложение":
   Execute as — **Me**, Who has access — **Anyone** (доступ защищён токеном
   на уровне кода).
6. Скопируйте URL веб-приложения (`https://script.google.com/macros/s/.../exec`)
   — это ваш `YOUR_APPS_SCRIPT_URL`.
7. При каждом изменении кода делайте новое развёртывание (Manage deployments
   → Edit → New version) — иначе изменения не применятся.

## б) n8n — импорт 4 workflow

Импортируйте по очереди (Workflows → Import from File):

- `mini-crm/workflow-1-new-lead.json`
- `mini-crm/workflow-2-reminders.json`
- `sales-engine/workflow-3-lead-finder.json`
- `sales-engine/workflow-4-approval-handler.json`

### Что заменить (плейсхолдеры)

Пройдитесь по каждому workflow и замените:

| Плейсхолдер | Где взять | Где встречается |
|---|---|---|
| `YOUR_APPS_SCRIPT_URL` | шаг "а".6 | во всех HTTP Request нодах к таблице |
| `YOUR_WEBHOOK_TOKEN` | шаг "а".4 | там же, рядом с URL |
| `YOUR_TELEGRAM_CHAT_ID` | раздел "в" | во всех Telegram-нодах |
| `YOUR_TELEGRAM_CREDENTIAL_ID` | раздел "в" | выбирается из выпадающего списка в ноде, не текстом |
| `YOUR_RANDOM_WEBHOOK_PATH` | придумайте сами | нода Webhook в workflow-1 |
| `YOUR_OUTSCRAPER_API_KEY` | раздел "е" | нода "Найти компании (Outscraper)" |
| `YOUR_GIGACHAT_CREDENTIAL_ID` | у вас уже настроен credential "GigaChat" | выбирается из списка в ноде "GigaChat: оценить компанию" |
| `YOUR_SHEET_URL` | ссылка на вашу таблицу | текст уведомлений в Telegram (необязательно, но удобно) |

Для полей вида `YOUR_..._CREDENTIAL_ID` не нужно вписывать текст руками —
откройте ноду, в поле Credential выберите (или создайте) нужный credential из
выпадающего списка, n8n сам подставит правильный ID.

Важные детали по каждому workflow:

- **workflow-1**: путь вебхука (`YOUR_RANDOM_WEBHOOK_PATH`) придумайте сами —
  любая длинная строка из букв/цифр, чтобы её нельзя было угадать (это
  дополнительная защита сверх токена).
- **workflow-2**: проверьте в настройках workflow (шестерёнка → Settings)
  часовой пояс — должен быть Europe/Moscow, иначе напоминание придёт не в
  10:00 по Москве.
- **workflow-3**: в ноде "Параметры поиска (меняйте здесь)" перед каждым
  запуском меняете нишу/город/лимит — код трогать не нужно.
- **workflow-4**: должен быть активен одновременно с workflow-3 — иначе
  нажатия кнопок не будут обрабатываться.

## в) Telegram-бот и chat ID

1. Напишите @BotFather → `/newbot` → следуйте инструкциям → получите токен
   бота.
2. В n8n: Credentials → New → Telegram API → вставьте токен → сохраните под
   именем, например, "Telegram account".
3. Узнать свой chat_id: создайте временный workflow с нодой **Telegram
   Trigger** (Updates: Message), запустите, напишите боту любое сообщение —
   в пришедших данных будет `message.chat.id`. Это и есть ваш
   `YOUR_TELEGRAM_CHAT_ID`. Временный workflow потом можно удалить.

## г) Инлайн-кнопки "Одобрить"/"Отклонить" — какой вариант проще

Есть два способа сделать кнопки в Telegram-сообщении через n8n:

1. **Стандартная Telegram-нода** (используется в этом проекте) — в поле
   "Reply Markup" выбираете "Inline Keyboard" и заполняете текст кнопки и
   `callback_data` в понятной форме, без ручного HTML/JSON. Минус: чуть менее
   гибко для сложных динамических клавиатур.
2. **HTTP Request к Telegram Bot API напрямую** — полностью гибко, но нужно
   вручную собирать JSON-структуру клавиатуры и следить за форматом запроса.

**Для новичка проще и надёжнее вариант 1** (стандартная нода) — именно он
использован в workflow-3. После импорта откройте ноду "Отправить карточку
лида" и убедитесь, что в Reply Markup уже видны две кнопки — если нет,
пересоздайте их через интерфейс (Add Button → впишите текст и callback_data)
по образцу `approve:{{ $json.id }}` / `reject:{{ $json.id }}`.

## д) Netlify — подключение webhook

1. Активируйте workflow-1 в n8n (тумблер Active).
2. Откройте ноду Webhook → скопируйте **Production URL** (не Test URL — Test
   URL работает только пока вы вручную нажали "Listen for test event").
3. В Netlify: Site configuration → Forms → Form notifications → Add
   notification → Outgoing webhook.
4. Event to listen for: New form submission. URL to notify: вставьте
   Production URL. Form: выберите вашу форму. Сохраните.

Подробный пошаговый тест — в [`test/test.md`](./test/test.md). Коротко:

5. Повторный запуск поиска на тех же компаниях → новых дублей не появляется.

## з) 5 частых причин, почему может не работать

1. **Ничего не приходит в Telegram вообще**
   → Проверьте, активен ли workflow (тумблер Active), и правильный ли
   Telegram credential выбран в ноде. Откройте n8n → Executions → посмотрите,
   дошло ли выполнение до Telegram-ноды.

2. **В Telegram пришло "⚠️ НЕ ЗАПИСАНО В ТАБЛИЦУ" / "⚠️ Ошибка в Sales
   Engine: ..."**
   → Это осознанно работающая защита — сообщение говорит, на каком именно
   шаге проблема (запись в таблицу / поиск компаний / GigaChat / проверка
   дублей). Идите проверять именно этот шаг: URL, токен или credential.

3. **Apps Script возвращает "Неверный или отсутствующий token"**
   → Значение `WEBHOOK_TOKEN` в Script Properties не совпадает один в один
   с тем, что вписано в n8n (лишний пробел — частая причина).

4. **После правки Code.gs ничего не изменилось**
   → Нужно новое развёртывание (Deploy → Manage deployments → Edit → New
   version), просто сохранить код в редакторе недостаточно.

5. **GigaChat-нода падает с ошибкой сертификата (TLS/SSL)**
   → GigaChat использует сертификат от Минцифры России, который не всегда
   есть в стандартном наборе доверенных сертификатов сервера. Проверьте с
   тем, кто настраивал credential "GigaChat" — возможно, на сервере n8n
   (Amvera) нужно установить этот корневой сертификат, либо (менее
   безопасный временный вариант) включить в ноде Options → "Ignore SSL
   Issues" — я не стал включать это по умолчанию, так как это ослабляет
   проверку подлинности сервера.

Отдельно, не про поломку, а про путаницу: если кнопки "Одобрить"/"Отклонить"
не реагируют — проверьте, что workflow-4 тоже активен (тумблер Active), а не
только workflow-3.
