# Мини-CRM для заявок TAINA Studio

Что получится:
1. Заявка с сайта (Netlify Forms) автоматически попадает строкой в Google Таблицу.
2. Вам сразу приходит уведомление в Telegram.
3. Раз в день бот присылает список заявок, на которые вы ещё не ответили.

Никакого ИИ и сложной логики здесь нет — только надёжная проводка данных:
Netlify → n8n → Google Таблица + Telegram.

---

## Важно про безопасность

- Нигде в файлах репозитория нет токенов, паролей или chat_id — только
  плейсхолдеры вида `YOUR_TELEGRAM_CHAT_ID`. Все реальные значения вы
  вставляете только в настройках n8n и Apps Script (Script Properties),
  не в код.
- Не публикуйте свой Apps Script URL и токен нигде, кроме настроек n8n.

## Что я проверил, а что нет (честно)

Из этой песочницы был заблокирован прямой доступ к docs.netlify.com,
docs.n8n.io и developers.google.com (сработал только веб-поиск по
кэшу Google, не прямой заход на страницы). Поэтому:

- **Подтверждено через официальные страницы n8n docs.n8n.io** (по
  результатам поиска, ссылающимся на эти страницы): поведение ноды
  Webhook (один HTTP-метод на ноду, Production URL активируется только
  при включённом workflow), ноды Telegram → Send Message (нужны chatId,
  text и credential с токеном бота), ноды Schedule Trigger (режим "Days"
  с триггером на конкретный час).
- **Подтверждено через developers.google.com** (по результатам поиска):
  что `doGet(e)`/`doPost(e)` — стандартные функции Web App в Apps Script,
  `e.postData.contents` содержит тело запроса, `ContentService` отдаёт
  JSON.
- **НЕ удалось проверить напрямую**: точную структуру JSON, которую
  Netlify присылает в исходящий webhook при отправке формы. По моим
  знаниям и по косвенным данным из форумов Netlify, поля формы обычно
  лежат в `data` (например `data.name`, `data.email`), но иногда — прямо
  в теле запроса. Поэтому нода "Собрать поля заявки" в workflow проверяет
  оба варианта. **После первого тестового отправления формы обязательно
  загляните в n8n → Executions → откройте выполнение → посмотрите, что
  реально пришло в ноду Webhook**, и при необходимости поправьте эту
  ноду (это одна строчка кода, я объясню ниже).
- В репозитории TAINA Studio (`clawdbot1`) я не нашёл HTML-формы сайта —
  этот репозиторий не связан с сайтом. Поэтому названия полей (name,
  email, phone, message) — стандартные, самые частые для Netlify Forms.
  Скрипт Apps Script устроен так, что **не обязательно, чтобы названия
  совпадали** — читайте раздел "Про названия полей" ниже.

## Шаг 1. Google Таблица

1. Создайте новую Google Таблицу (sheets.google.com → пустая таблица).
2. Переименуйте первый лист в `Заявки` (это важно, скрипт ищет лист с
   таким названием; если не найдёт — возьмёт первый лист).
3. В первой строке впишите заголовки колонок, например:

   | Дата | name | email | phone | message | Статус | Дата ответа |
   |------|------|-------|-------|---------|--------|-------------|

   **Про названия полей**: заголовки `name`, `email`, `phone`, `message`
   должны совпадать с названиями полей вашей реальной формы на сайте
   (атрибут `name="..."` у `<input>`/`<textarea>` в HTML). Если у вас
   поля называются иначе (например `full_name`, `phone_number`) —
   просто переименуйте заголовки в таблице под них. Менять код скрипта
   не нужно: он сам подставляет значения по названию колонки.
   Заголовки `Дата`, `Статус`, `Дата ответа` — служебные, их называть
   нужно именно так (или поменять в `Code.gs`, если хотите свои
   названия).

## Шаг 2. Apps Script (веб-приложение для записи в таблицу)

1. В открытой таблице: Расширения → Apps Script.
2. Удалите содержимое `Code.gs` по умолчанию и вставьте код из файла
   [`apps-script/Code.gs`](./apps-script/Code.gs) этого репозитория.
3. Задайте секретный токен (чтобы вашу таблицу не мог дёргать кто угодно
   в интернете):
   - Слева значок шестерёнки "Настройки проекта" (Project Settings).
   - Раздел "Свойства скрипта" (Script Properties) → "Добавить свойство
     скрипта".
   - Property: `SHARED_TOKEN`
   - Value: придумайте длинную случайную строку (например, откройте
     https://www.uuidgenerator.net и скопируйте UUID — это будет ваш
     токен). Запишите его себе, он понадобится в n8n.
4. Разверните как веб-приложение: кнопка "Развернуть" (Deploy) →
   "Новое развёртывание" (New deployment) → тип "Веб-приложение" (Web app).
   - Execute as (Запуск от имени): **Me** (вы).
   - Who has access (У кого есть доступ): **Anyone** (Все) — доступ всё
     равно защищён токеном на уровне кода.
5. Скопируйте выданный URL веб-приложения (вида
   `https://script.google.com/macros/s/AKfycb.../exec`) — он понадобится
   в n8n.
6. При каждом изменении кода делайте новое развёртывание (Manage
   deployments → Edit → New version), иначе изменения не применятся к
   рабочему URL.

## Шаг 3. Telegram

1. Напишите @BotFather в Telegram → `/newbot` → следуйте инструкциям →
   получите токен бота (строка вида `123456:ABC-DEF...`).
2. Узнайте свой chat_id одним из способов:
   - Напишите что-нибудь своему новому боту, затем в n8n создайте
     временный workflow с нодой "Telegram Trigger" (On message),
     запустите его и посмотрите пришедший `chat.id`.
   - Или добавьте бота в нужный чат/группу и посмотрите chat_id через
     `Telegram Trigger` таким же способом.
3. Токен бота и chat_id никуда, кроме n8n, вставлять не нужно.

## Шаг 4. n8n — workflow «Новая заявка»

Можно импортировать готовый файл или собрать вручную — оба варианта
описаны, на случай если импорт не сработает из-за версии вашего n8n.

### Вариант А: импорт

1. В n8n: Workflows → Import from File → выберите
   [`n8n/workflow-new-lead.json`](./n8n/workflow-new-lead.json).
2. Откройте ноду **"Записать в Google Таблицу"** → вставьте вместо
   `YOUR_APPS_SCRIPT_ID` реальный URL из шага 2, и вместо
   `YOUR_SHARED_TOKEN` — ваш токен.
3. Откройте ноду **"Уведомление в Telegram"** → в поле chatId вставьте
   свой chat_id вместо `YOUR_TELEGRAM_CHAT_ID` → в Credentials создайте
   новый Telegram credential и вставьте токен бота.
4. Сохраните workflow и включите тумблер **Active**.
5. Откройте ноду Webhook → скопируйте **Production URL** (не Test URL) —
   он понадобится в Netlify.

### Вариант Б: вручную (если импорт не сработал)

1. Нода **Webhook**: HTTP Method = POST, Path = `taina-new-lead`,
   Response Mode = "Immediately" (или "onReceived").
2. Нода **Code** (JavaScript), подключить после Webhook:
   ```js
   const body = $input.first().json.body || $input.first().json;
   const data = body.data || body;
   return [{ json: data }];
   ```
3. Нода **HTTP Request**: Method = POST, URL = ваш Apps Script URL,
   Query Parameters: `action=addLead`, `token=<ваш токен>`, Body = JSON,
   значение — весь входящий объект (`{{ $json }}`).
4. Нода **Telegram** → операция Send Message, chatId = ваш chat_id,
   текст — например `{{ JSON.stringify($json) }}` для начала (потом
   можно красиво оформить).
5. Соединить ноды по порядку, сохранить, включить Active, скопировать
   Production URL из ноды Webhook.

## Шаг 5. Netlify — подключаем форму к n8n

1. Зайдите в Netlify → ваш сайт → **Site configuration → Forms →
   Form notifications** (может называться "Уведомления о формах").
2. Нажмите **Add notification → Outgoing webhook**.
3. Event to listen for: **New form submission**.
4. URL to notify: вставьте Production URL из n8n (шаг 4.5).
5. Form: выберите вашу форму заявки (если форм несколько).
6. Сохраните.

## Шаг 6. Тест первого workflow

1. Отправьте тестовую заявку через реальную форму на сайте (или через
   Netlify → Forms → откройте форму → "Simulate a submission", если
   такая опция есть в вашем плане).
2. Проверьте:
   - Пришло ли сообщение в Telegram.
   - Появилась ли новая строка в Google Таблице.
   - Если нет — откройте в n8n **Executions**, найдите последнее
     выполнение, посмотрите, на какой ноде остановилось и что пришло в
     Webhook (см. раздел "Что я проверил" выше — возможно, нужно
     поправить ноду "Собрать поля заявки" под реальную структуру данных
     Netlify).

## Шаг 7. n8n — workflow «Напоминание о заявках без ответа»

1. Импортируйте [`n8n/workflow-daily-reminder.json`](./n8n/workflow-daily-reminder.json)
   (или соберите вручную по той же логике, что и выше: Schedule Trigger
   → HTTP Request (GET, action=getUnanswered) → IF (count > 0) → Code
   (собрать текст) → Telegram).
2. Вставьте в ноду **"Получить заявки без ответа"** ваш Apps Script URL
   и токен (как в шаге 4.2).
3. Вставьте в ноду **"Отправить напоминание"** свой chat_id и Telegram
   credential (как в шаге 4.3).
4. В ноде **"Каждый день в 10:00"** при желании поменяйте час
   напоминания.
5. Сохраните и включите Active.

## Как отмечать заявку «отвечено»

Просто откройте Google Таблицу и в колонке **Статус** напротив нужной
строки впишите слово `Отвечено`. При следующей ежедневной проверке эта
заявка уже не попадёт в напоминание. Никаких кнопок и дополнительных
действий в n8n для этого не нужно — это самый простой вариант для
таблицы, которую ведёт человек, а не программа.

## Если что-то пошло не так

- **В Telegram ничего не приходит**: проверьте в n8n Executions — на
  какой ноде остановилось выполнение. Частая причина — неверный
  Apps Script URL/токен или незаполненный chat_id.
- **В таблице пусто, хотя Telegram сообщение пришло**: значит нода
  "Записать в Google Таблицу" ошиблась, но workflow продолжил работу
  (это специально настроено, чтобы уведомление не терялось). Проверьте
  URL и токен в этой ноде и в Script Properties Apps Script.
- **Apps Script возвращает "Неверный или отсутствующий token"**:
  проверьте, что значение `SHARED_TOKEN` в Script Properties совпадает
  один в один с тем, что вставлено в n8n (без лишних пробелов).
- **После правки Code.gs ничего не изменилось**: нужно сделать новое
  развёртывание (Deploy → Manage deployments → Edit → New version), а
  не просто сохранить код.
